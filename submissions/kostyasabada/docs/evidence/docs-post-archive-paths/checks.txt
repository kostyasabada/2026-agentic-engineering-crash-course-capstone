The script runs the pinned CLI directly, `OPENSPEC_TELEMETRY=0 ./node_modules/.bin/openspec list --json`, and prints its output, which Claude Code adds to the new session's context. It does not use `npm run`, because npm writes debug logs under `~/.npm/_logs` on every run (user decision, design D8). `OPENSPEC_TELEMETRY=0` is OpenSpec's documented telemetry opt-out: without it, a run sends an anonymous usage event once the global config records the telemetry notice as seen, and it writes the global config file only as a one-time copy of an existing `~/.config/openspec/config.json` into a different `XDG_CONFIG_HOME`; with no config anywhere it writes nothing. If the CLI or `node` is missing, the command fails, or it takes longer than 10 seconds, the script prints a one-line notice with the manual command (`npm run --silent openspec -- list --json`) instead; it always exits 0 and writes no files. The 10-second `timeout` sends SIGTERM only: a CLI process that ignored SIGTERM would keep the script waiting until it ended, bounded by Claude Code's 15-second hook timeout (the backstop). Because the script calls `node` directly, `timeout -k 2 10` would kill such a process after about 12 seconds (measured in the task 1.5 review, which then reported status 137 instead of the timeout reason); this is a possible later hardening, not a current need, since the real OpenSpec CLI does not ignore SIGTERM.
